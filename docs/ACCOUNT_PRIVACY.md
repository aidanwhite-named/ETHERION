# 회원가입 · 개인정보 — 조사와 설계 (2026-11-24)

서버를 바깥에 열고 회원가입을 받기 전에 정할 것을 모았다.
**이 문서는 조사 정리이지 법률 자문이 아니다.** 조문 번호 · 시행일은 2026-11 기준 검색으로 확인한 것이고, 해설 글마다 조금씩 다른 곳은 "확인 필요"로 적었다. 실제로 열기 전에 [국가법령정보센터](https://www.law.go.kr) 원문과 [개인정보보호위원회](https://www.pipc.go.kr) 안내를 한 번 더 본다. 돈을 받기 시작하면 전문가에게 한 번 보이는 편이 좋다.
아직 서버 코드는 고치지 않았다(5장의 순서는 계획).

## 0. 결론 먼저

1. **개인정보를 "보관하면 안 된다"는 아니다.** 법은 *필요한 최소한만 모으고, 목적이 끝나면 지체 없이 파기하라*고 한다(개인정보 보호법 제16조 · 제21조). 주민등록번호만은 법에 근거가 없으면 아예 받을 수 없다(제24조의2) — "요새는 보관하면 안 된다"는 인상은 여기서 온 것으로 보인다. 다만 **안 가진 정보는 새지도 않고 의무도 줄어든다** — 방향은 맞다.
2. **ETHERION이 받을 것은 이메일 주소 하나 + 모험가 이름(닉네임).** 실명 · 생년월일 · 전화번호 · 주소 · 성별은 받지 않는다. 비밀번호도 두지 않는 쪽을 추천한다.
3. **가입 방식은 "메일로 받은 6자리 코드 넣기"가 무난하다 — 맞다.** 한 걸음 더 가서 가입뿐 아니라 **로그인도 매번 코드로**(비밀번호 없음) 하면 암호 저장 · 암호 찾기 · 암호 유출 걱정이 통째로 사라진다. 지금의 "필멸자(손님)로 바로 시작"은 그대로 두고, 손님이 나중에 메일을 연결하면 계정이 된다.
4. **꼭 해야 할 것**(체크리스트는 6장): 개인정보 처리방침 공개 · 가입 때 수집 · 이용 동의 · 만 14세 미만 가입 막기(또는 법정대리인 동의) · https · 탈퇴하면 지움 · 접속 기록과 백업의 보관 기한 · 유출되면 72시간 안에 알리고 신고.

## 1. 지금 서버는 무엇을 갖고 있나 (v3.22 시험 서버)

| 무엇 | 어디 | 개인정보인가 |
|---|---|---|
| 모험가 이름(= 로그인 ID) | `server/data/db.json` `users[id]` | 그 자체로는 약하지만 계정 식별자 — 개인정보로 다룬다 |
| 암호 | 같은 곳 `pw` (scrypt 해시 + 소금) | 인증정보. 이미 일방향 암호화 — 기준에 맞는다 |
| 로그인 세션 토큰 | `db.sessions` (평문 토큰, 일반 30일) | 인증정보. 해시로 바꿀 것(3장) |
| 접속 주소(IP) | `server/logs/server.log` — 로그인 실패 · 가입 제한 기록 | 개인정보(온라인 식별자). **보관 기한이 없다** |
| 게임 데이터(보유 카드 · 덱 · 지갑 · 장부 · 전적 · 거래 기록) | `users[id]` | 계정에 묶인 이용 기록 |
| 하루 백업 | `server/data/backup/` 14~30개 | 위 전부의 사본 |
| 이메일 · 실명 · 생년월일 · 전화 | **없음** | — |

좋은 점: 이미 거의 아무것도 모으지 않는다. `server/data/` · `config.json` · `logs/`는 git에 올라가지 않는다.
바깥에 열기 전에 손볼 점: 암호 찾기가 없음(메일이 없으니) · 로그 보관 기한 없음 · 탈퇴(계정 지우기) 기능 없음 · 처리방침 · 동의 화면 없음 · 채팅을 서버로 옮기면 그 기록도 개인정보 처리 대상이 됨.

## 2. 법 · 규정 — 한국에서 회원가입을 받을 때

개인 개발자여도 회원 정보를 모아 서비스에 쓰면 "개인정보처리자"다(영리 여부 · 규모와 무관). 2020년에 정보통신망법의 개인정보 규정이 개인정보 보호법으로 합쳐졌고, 2023-09 개정으로 온라인 사업자 특례도 일반 규정으로 통합됐다. 그래서 볼 법은 사실상 **개인정보 보호법(+ 시행령 · 안전성 확보조치 기준 고시)** 하나다.

### 2.1 게임이라서 더 볼 것 (개인정보 밖 — 따로 확인할 숙제)

- **강제적 셧다운제(밤 12시~6시)는 2022-01-01 폐지.** 지금은 보호자 · 본인이 원하면 시간을 정하는 게임시간 선택제만 남았다([전자신문](https://www.etnews.com/20210825000041)).
- **게임산업법 제12조의3(과몰입 예방조치)** 은 온라인 게임에 가입 때 실명 · 나이 확인과 본인인증, 청소년의 법정대리인 동의를 요구한다. 그러나 시행령 제8조의3이 **중소기업이 제공하는 게임물을 빼 준다**(전년 매출 50억 원 이상은 일부만 면제). 개인 · 소규모인 ETHERION은 이 본인인증 의무에서 빠지는 것으로 읽힌다 — **그래서 이메일만으로 가입받을 수 있다.** 현행 조문은 열기 전에 확인([시행령 제8조의3](https://law.go.kr/LSW/lsRvsDocListP.do?lsId=010307&chrClsCd=010102), [헌재 결정](https://www.law.go.kr/LSW/detcInfoP.do?mode=1&detcSeq=44953)).
- **등급분류**: 한국에서 게임을 공개 서비스하려면 원칙적으로 등급분류를 받아야 한다. 개인 · 동호회가 **영리 목적 없이** 공개하는 게임은 면제 근거가 있다(2019 시행령 개정). 유료 결제를 붙이는 순간 면제에서 벗어난다 — 구글 · 애플 스토어로 내면 스토어의 자체등급분류로 해결되고, 웹만으로 유료 서비스하면 게임물관리위원회에 신청한다. 2026년에 게임산업법 전부개정이 진행 중이라 바뀔 수 있다([전자신문 2026-08](https://m.etnews.com/20260806000246), [법률신문](https://www.lawtimes.co.kr/news/articleView.html?idxno=207287)). **개인정보와 별개의 큰 숙제라 따로 조사할 것.**
- **결제가 생기면**: 전자상거래법에 따라 계약 · 청약철회 기록 5년, 대금 결제 · 재화 공급 기록 5년, 소비자 불만 · 분쟁 처리 기록 3년을 보관해야 한다(이때는 "보관해야 하는" 쪽). 통신판매업 신고 · 사업자 정보 표시 · 미성년자 결제의 법정대리인 동의(취소권) · 확률형 아이템 확률 표시(게임산업법 제33조, 2024-03 시행 — 카드 뽑기 · 수레바퀴를 돈으로 팔면 해당)도 생긴다. 카드 번호는 결제대행사(PG)가 갖고 우리는 갖지 않는다.
- **채팅을 서버로 옮기면** 채팅 기록의 보관 기한(예: 30일)과 신고 처리 절차를 처리방침 · 약관에 넣는다.

### 3.1 수집 항목 (최소안)

| 비밀번호 | **✕** | 코드 로그인이라 필요 없음 | — |
| 실명 · 생년월일 · 성별 · 전화번호 · 주소 | **✕** | 쓸 곳이 없다 | — |
| 주민등록번호 · 본인인증값(CI/DI) | **✕** | 받으면 안 됨 / 의무 대상 아님 | — |

| 결제 정보 | 나중에 — 주문 번호 · 금액 · 때만 | 카드 번호는 PG가 가짐 | 결제를 붙일 때 문서를 고친다 |

### 3.2 저장 방식

- **이메일**
  - 받으면 먼저 다듬는다: 앞뒤 공백 제거 · 소문자. (Gmail의 점 · `+꼬리표`를 뭉개지는 않는다 — 남의 주소 규칙을 짐작하지 않는다.)
  - `emailKey = HMAC-SHA256(서버 비밀, 다듬은 주소)` — 가입 중복 검사 · 로그인 때 계정 찾기에 쓴다. 맨 SHA-256은 주소 목록을 대입해 금방 풀리므로 반드시 서버 비밀을 섞는다.
  - `emailEnc = AES-256-GCM(열쇠, 원문)` — 메일을 보낼 일이 있어서(휴면 예고 · 유출 통지) 원문을 되살릴 수 있어야 한다. 해시만 두면 이 통지를 못 한다. **의무는 아니지만** db.json이나 백업이 새어도 주소 목록이 드러나지 않게 하려는 것.
  - 열쇠 두 개(`emailHmacKey` · `emailEncKey`)는 `server/config.json`에(또는 환경 변수) — **db.json · 백업과 다른 곳**에 둔다. 백업을 다른 기기로 복사할 때 config.json은 같이 넣지 않는다. 열쇠를 잃으면 메일을 못 보내고 로그인도 못 찾으니 열쇠만 따로 안전한 곳(암호 관리자)에 적어 둔다.
  - 화면 · 로그 · 관리자 보관소에는 `ab***@gm***.com`처럼 가려서만 보인다. 관리자 스냅샷(`snapshot`의 `others`)에 이메일 칸을 넣지 않는다.
- **인증 코드**
  - 6자리 숫자, `crypto.randomInt`로 만든다. **10분** 뒤 무효, **한 번 쓰면 무효**, 새 코드를 보내면 앞의 것은 무효.
  - 저장은 `HMAC(서버 비밀, 코드 + emailKey)`만. 평문 코드를 db · 로그에 남기지 않는다.
  - 코드 한 개에 **틀리기 5번**이면 버린다(6자리 = 100만 가지라 5번이면 맞힐 확률 0.0005%).
  - 보내기 제한: 같은 주소 1분에 1통 · 1시간에 5통 · 하루 10통, 같은 접속 주소 1시간에 10통. 지금 있는 `limited` / `hit` 틀을 그대로 쓴다.
  - **가입한 주소인지 알려 주지 않는다**: 어떤 주소를 넣어도 "코드를 보냈습니다"로 같게 답한다. 가입 안 된 주소면 그 자리에서 가입으로 이어진다(가입과 로그인이 한 화면).
  - 메일 본문: 코드 · 10분 안내 · "요청한 적이 없으면 이 메일을 무시하세요". 링크는 넣지 않는다(피싱 메일과 구별되게 — "ETHERION은 메일로 링크를 보내지 않습니다").
  - 코드를 넣는 화면에 `autocomplete="one-time-code"` · `inputmode="numeric"`.
- **세션**
  - 지금처럼 무작위 토큰(24바이트)을 주되 **db에는 SHA-256 해시만** 저장한다(백업이 새어도 로그인된 채로 못 쓰게).
  - 30일 안 쓰면 끝(지금과 같음). "모든 기기에서 나가기" 단추. 이메일을 바꾸면 다른 세션을 모두 끊는다.
- **지금 있는 ID + 암호 계정**
  - 시험 서버 계정은 암호 로그인을 그대로 두고, 들어온 뒤 "메일 연결"을 권한다(연결하면 암호를 지운다). 정식으로 열 때 새로 시작해도 된다(SERVER_PLAN.md의 방침과 같음).
  - 관리자(`admin`)는 암호 + Tailscale 안에서만 — 그대로.
- **손님(필멸자)**
  - 지금처럼 이메일 없이 바로 시작. 개인정보를 받지 않는다(브라우저의 토큰뿐).
  - "모험가로 등록"을 누르면 메일 + 코드로 그 손님 데이터가 그대로 계정이 된다.
  - 세션이 끝난 손님은 지금처럼 저절로 지워진다(`sweepSessions`).

| 메일 인증을 끝내지 않은 가입 시도 | 10분(코드) / 24시간(제한 계수) | 저절로 지움 |

| 메일 발송 업체의 발송 기록 | 업체 설정에서 가장 짧게(보통 3~30일) | 업체가 지움 — 처리방침에 적는다 |
| (결제가 생기면) 거래 기록 | 5년 — 전자상거래법 | 계정과 떼어 따로 보관 |

### 3.4 탈퇴

- 설정 화면에 "모험가 지우기". 메일 코드로 한 번 더 확인하고 바로 지운다(유예를 두려면 "7일 안에 다시 들어오면 취소"처럼 화면과 처리방침에 적는다 — 처음엔 유예 없이 단순하게).
- 지우는 것: `users[id]` 전체(이메일 · 덱 · 지갑 · 장부) · 그 사람의 세션 · 교역소에 맡긴 것(거래를 거두고 정산한 뒤).
- 남는 것: 다른 사람의 거래 소식 · 전적에 남은 닉네임 → "떠난 모험가"로 바꾼다. 닉네임은 30일 동안 다시 못 쓰게만 잠근다(사칭 막기 — 이메일은 남기지 않는다).
- 백업에는 14일 남는다고 처리방침에 적는다. 백업을 되살릴 때는 그 사이 탈퇴한 사람을 다시 지운다(탈퇴자 `emailKey` 목록을 14일 동안만 둔다).
- 열람 · 정정 · 삭제 · 처리정지 요청(법 제35~37조)은 문의 메일로 받고 10일 안에 답한다. "내 데이터 내려받기"는 `GET /api/me`의 스냅샷을 파일로 주면 된다.

### 3.5 운영 · 보안

- **https만.** Cloudflare 터널 또는 도메인 + 인증서. http로는 로그인 화면을 열지 않는다. Cloudflare를 쓰면 그것도 위탁(국외) — 처리방침에 적는다.
- 서버 컴퓨터: 디스크 암호화(맥 FileVault) · OS 자동 업데이트 · 관리자 접근은 Tailscale 안에서만(지금 설정 그대로).
- 보내는 메일의 도메인에 SPF · DKIM · DMARC를 건다(안 하면 스팸함으로 간다). 메일 서비스가 안내하는 DNS 줄 3~4개.
- 로그에 이메일 원문 · 코드 · 토큰을 찍지 않는다(`logOp`가 args를 찍는 곳에서 가린다).
- 저장소에 `server/data` · `config.json` · `logs`가 올라가지 않는 것을 유지(.gitignore — 지금 그대로).

### 3.6 사고가 났을 때 (미리 적어 두는 순서)

1. 서버를 끊고(터널 내림) 무엇이 새었는지 본다: db.json · 백업 · 로그 · config.json(열쇠) 중 어느 것인지.
2. 세션을 모두 끊고 열쇠(`emailEncKey` · `emailHmacKey` · 관리자 암호)를 바꾼다.
3. **72시간 안에** 해당 회원에게 메일 통지: 새어 나간 항목 · 때와 경위 · 우리가 한 일 · 회원이 할 일(이 주소로 오는 피싱 주의) · 문의처.
4. 해킹(바깥에서의 불법 접근)이거나 1천 명 이상이면 **72시간 안에 신고**: [개인정보 포털](https://www.privacy.go.kr) 유출 신고 또는 KISA(국번 없이 118).
5. 한 일을 기록으로 남긴다.

| (c) 소셜 로그인(구글 · 카카오 · 애플) | 중간~높음 — 업체마다 개발자 등록 · 심사 · OAuth. 카카오는 사업자 정보 · 처리방침 주소 요구, 애플은 연 $99, iOS 앱에 소셜 로그인을 넣으면 애플 로그인도 넣어야 함 | 무료(애플 개발자 비 제외) | 업체가 준 고유 번호만 받으면 **가장 적음**(이메일도 안 받을 수 있음) | 가장 편함(누르면 끝) | 업체 계정이 없는 사람 · 쓰기 싫은 사람. 업체 정책에 묶임. 처리방침에 "제공받는 항목"을 적어야 함 |

### 4.1 추천

**(d) + (a)로 연다. (c)는 사람이 늘면 구글 하나부터 덧붙인다. (b)는 하지 않는다.**

- "메일을 보내고 코드를 확인"은 무난하다 — 가장 흔하고, 받는 정보가 이메일 하나이고, 본인인증 업체 계약이 필요 없다.
- 거기서 비밀번호까지 받으면 (b)가 되는데, 어차피 메일 발송을 붙였다면 암호는 **일만 늘리고 위험만 더한다**(해시 저장 · 찾기 · 대입 공격). 코드 로그인이면 "암호 찾기"가 곧 로그인이다.
- 번거로움(매번 메일함)은 세션 30일 + "이 기기 기억"으로 줄인다. 나중에 **패스키(WebAuthn)** 를 덧붙이면 메일 없이 지문 · 얼굴로 들어온다 — 패스키 공개 열쇠는 개인정보 부담이 거의 없다.
- 14세 미만과 "일단 해 보려는 사람"은 손님으로 받는다. 손님은 개인정보를 주지 않으므로 동의 화면도 필요 없다(약관 안내만).
- 가입 흐름: 로그인 화면 → 이메일 넣기 → 코드 6자리 → (처음이면) 닉네임 + 동의 체크 2개 → 시작. 손님이면 설정에서 "모험가로 등록"이 같은 흐름.

### 4.2 메일 발송 서비스 후보 (2026-11 검색 기준 — 가입 전에 요금표 다시 확인)

코드 메일은 하루 신규 가입 + 재로그인 수만큼 나간다. 하루 활성 300명이어도 30일 세션이면 하루 수십 통 수준이라 **무료 구간으로 충분**하다.

| 서비스 | 무료 | 유료 시작 | 메모 |
|---|---|---|---|
| [Resend](https://resend.com/pricing) | 월 3,000통(하루 100통) | 월 $20 / 5만 통 | API가 단순(HTTP 한 번). 미국 — 국외 이전 고지 |
| [Brevo](https://www.brevo.com/pricing/) | 하루 300통 | 월 $9쯤부터 | 무료 한도가 넉넉. 프랑스(EU) |
| [Postmark](https://postmarkapp.com/pricing) | 월 100통(시험용) | 월 $15 / 1만 통 | 도착률 평이 좋음. 미국 |
| [Amazon SES](https://aws.amazon.com/ses/pricing/) | 2026-07부터 새 계정 무료 구간이 바뀌었다는 글이 있음 — 확인 필요 | 1,000통에 $0.10쯤 | 가장 쌈. 설정이 번거롭고 처음엔 발송 제한(샌드박스) 해제 신청. 서울 리전을 고르면 국내 처리 |
| [NHN Cloud Email](https://www.nhncloud.com/kr/service/notification/email) · [네이버 클라우드 Cloud Outbound Mailer](https://www.ncloud.com/product/applicationService/cloudOutboundMailer) | 소량 무료 또는 통당 1원 안쪽 | 쓴 만큼 | **국내 업체 — 국외 이전 고지가 필요 없다.** 네이버 · 다음 메일 도착률에 유리하다는 평. 사업자 등록 없이 개인 가입이 되는지 확인 필요 |

비교 글: [makerkit 2026](https://makerkit.dev/blog/saas/best-transactional-email-provider-saas), [dev.to](https://dev.to/devtoolpicks/resend-vs-postmark-vs-mailgun-for-solo-developers-in-2026-5gfl).

- 고르는 기준: 처음에는 **Resend나 Brevo(무료 · 10분이면 붙음)**, 처리방침에 국외 이전 한 줄. 국외 이전 칸을 아예 없애고 싶으면 국내 서비스나 SES 서울.
- 어느 쪽이든 **보내는 주소용 도메인이 있어야 한다**(예: `no-reply@게임도메인`). 도메인은 연 1~2만 원. Gmail 주소로는 대량 발송 서비스가 안 된다.
- 코드는 `mailer.send(to, code)` 한 함수 뒤에 두어 업체를 바꾸기 쉽게 한다. Node 내장 `fetch`로 부르면 npm 꾸러미 없이 된다(지금 서버의 "바깥 꾸러미 없음"을 유지).
- 그 밖의 비용: 도메인 연 1~2만 원 · Cloudflare 터널 무료 · 서버는 집의 맥(전기료). 클라우드로 옮기면 월 5천~1만 원대 작은 서버.

### 4.3 필요한 화면 · 문서

**화면**
1. 로그인 = 가입 한 화면: 이메일 칸 → 코드 칸(다시 보내기는 60초 뒤) → 처음이면 닉네임.
2. 동의(처음 가입할 때만): 표 하나 — 목적(계정 만들기 · 로그인 · 꼭 필요한 알림) / 항목(이메일 · 닉네임) / 보유 기간(탈퇴할 때까지, 2년 미접속이면 삭제) / "동의하지 않을 수 있으며, 그러면 손님으로만 이용할 수 있습니다". 체크: `[필수] 개인정보 수집 · 이용 동의` · `[필수] 이용약관 동의` · `[필수] 만 14세 이상입니다`. 미리 체크해 두지 않는다.
3. 설정 → 계정: 가려진 이메일 · 이메일 바꾸기(새 주소로 코드) · 모든 기기에서 나가기 · 내 데이터 내려받기 · 모험가 지우기.
4. 손님 화면에 "모험가로 등록하면 다른 기기에서도 이어집니다" 안내.
5. 로그인 화면 아래 `개인정보 처리방침 · 이용약관` 링크(늘 보이게, 처리방침 글자를 굵게).

**개인정보 처리방침 목차 초안** (`privacy.html` — 개인정보위 [처리방침 작성지침](https://www.pipc.go.kr)의 틀을 따른다. [개인정보 포털](https://www.privacy.go.kr)에 처리방침을 만들어 주는 도구가 있다)
1. 처리 목적
2. 처리하는 항목과 수집 방법(가입 때 직접 입력 / 접속할 때 저절로 생기는 접속 주소 · 접속 시각)
3. 보유 기간(3.3의 표)
4. 파기 절차와 방법
5. 제3자 제공 — 하지 않음
6. 처리 위탁 — 메일 발송 업체 · (쓰면) Cloudflare · 호스팅
7. 국외 이전 — 받는 자 · 나라 · 항목 · 목적 · 보유 기간 · 거부 방법(해외 업체를 쓸 때만)
8. 만 14세 미만 — 가입받지 않음
9. 이용자의 권리와 행사 방법(열람 · 정정 · 삭제 · 처리정지 · 탈퇴)
10. 안전성 확보조치(암호화 · 접근 제한 · 접속 기록)
11. 자동 수집 장치 — 쿠키를 쓰지 않음(로그인 토큰은 브라우저 저장소에) · 분석 도구 없음
12. 개인정보 보호책임자 · 문의처
13. 권익침해 구제 방법(개인정보분쟁조정위 1833-6972 · 개인정보침해신고센터 118 · 대검찰청 1301 · 경찰청 182)
14. 방침 변경(시행일 · 이전 버전 보기)

**이용약관**(`terms.html`): 계정 · 닉네임 규칙 · 게임 안 재화(조각 · 카드)는 현금 가치가 없고 서비스 종료 · 초기화될 수 있음 · 교역소 규칙 · 금지 행위 · 이용 제한 · 책임의 한계 · 시험 운영 중 데이터 초기화 가능. 결제를 붙일 때 청약철회 · 환불 조항을 더한다.

## 5. 구현 순서 (사용자 결정 뒤)

정할 것 먼저: ① 비밀번호 없는 코드 로그인으로 갈지 ② 도메인 이름 ③ 메일 서비스(해외 무료 / 국내) ④ 시험 서버 계정을 살릴지 새로 시작할지 ⑤ 14세 미만은 손님만으로 할지.

1. **문서**: `privacy.html` · `terms.html` 초안, 문의용 메일 주소 만들기.
2. **도메인 · https · 메일**: 도메인 연결, Cloudflare 터널 고정 주소, 메일 서비스 가입 · SPF / DKIM / DMARC, `server/mailer.js`(시험 때는 서버 창에 코드를 찍는 가짜 발송기).
3. **서버**: `POST /api/auth/start {email}` → 코드 발송 · `POST /api/auth/verify {email, code, nick?, agree}` → 세션. 이메일 HMAC / 암호화 · 코드 해시 · 제한 · 세션 토큰 해시. 손님 → 계정 연결(`/api/auth/link`). `config.json`에 열쇠 3개를 처음 켤 때 만들기.
4. **게임 화면**(`js/screens.js` 입장 화면 · `js/net.js`): 이메일 → 코드 → 닉네임 · 동의. 파일로 연 게임(오프라인 · PC 앱)은 지금처럼 로컬 그대로.
5. **계정 관리**: 탈퇴(지우기) · 이메일 바꾸기 · 모든 기기에서 나가기 · 내 데이터 내려받기.
6. **정리 작업**: 로그 날짜별 파일 + 30일 삭제 · `backupKeep` 14 · 2년 미접속 예고 메일과 삭제 · 로그에서 이메일 / 코드 / 토큰 가리기.
7. **시험**: `tools/auth/test.js` — 코드 만료 · 5번 틀림 · 다시 보내기 제한 · 가입 여부를 알려 주지 않음 · 탈퇴 뒤 흔적 없음 · db.json에 이메일 원문이 없음.
8. **열기 전 점검**: 6장 체크리스트.
9. (나중) 구글 로그인 · 패스키 · 결제를 붙일 때의 문서 고치기.

`docs/SERVER.md`의 "암호 찾기는 없다" · 계정 요청 표 · `SERVER_PLAN.md`는 3번을 할 때 함께 고친다.

## 6. 바깥에 열기 전 체크리스트

- [ ] 받는 것은 이메일 · 닉네임뿐인지(화면에 다른 칸이 없는지)
- [ ] 개인정보 처리방침이 로그인 화면에서 한 번에 열리는지 · 시행일이 적혔는지
- [ ] 가입 때 수집 · 이용 동의(목적 · 항목 · 기간 · 거부권)를 받고 기록(버전 · 시각)이 남는지
- [ ] "만 14세 이상" 확인이 있는지
- [ ] https로만 열리는지
- [ ] db.json에 이메일 원문 · 평문 코드 · 평문 토큰 · 암호가 없는지
- [ ] 열쇠(config.json)가 백업과 다른 곳에 있고 따로 적어 두었는지
- [ ] 코드: 10분 만료 · 한 번만 · 5번 틀리면 버림 · 보내기 제한
- [ ] 탈퇴가 되고 바로 지워지는지 · 백업 14일 · 로그 30일
- [ ] 처리방침에 메일 발송 업체(위탁 · 국외 이전)가 적혔는지
- [ ] 문의용 메일 주소 · 보호책임자가 적혔는지
